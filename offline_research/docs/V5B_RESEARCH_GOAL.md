# V5B research-heavy parallel discovery

This is a separate bounded development campaign for KLAX daily maximum-temperature contracts. The objective is to discover and attempt to falsify new causal hypotheses that may support at least 10% expected net return per purchased contract on entry outlay including fees. No gain is guaranteed. Simulated development return is not account profit.

## Why this campaign exists

V5A implements four fixed parameter families around one shared incumbent, without deduplication or independent hypothesis populations. Its preserved provisional leader has 36 simulated trades and 17.7007% aggregate development return, but one chronological fold loses 100%. V5B preserves that baseline and its entire campaign. It introduces agent-authored hypotheses, independent populations, canonical deduplication, explicit falsification, cross-colony review, and compatible synthesis.

## Data and confirmation boundary

Use only the already exposed 64 June 1–August 3, 2026 development dates. These are adaptively reused development observations, not new out-of-sample evidence. All historical input bindings must be checked before execution. The existing August 4–31 holdout is reserved for V5A even while sealed. V5B cannot open it, import its results into discovery, or call it an independent V5B confirmation. A separate eligible untouched period is required. If unavailable, save a development-only conclusion and a confirmation blocker; do not manufacture a final evaluation.

The current curated probability file provides calibrated and raw bracket probabilities. Model-cycle changes, individual ensemble members, alternate decision-time replay and depth imbalance require separately audited features; mark unavailable hypotheses as data-blocked. Do not substitute guessed fields or label-derived regimes.

## Two goals

1. Implement and verify the research foundation: four colony charters, typed hypotheses, independent populations, stable fingerprints, deterministic evaluation, complete ledgers, cross-review, Pareto archive, source bindings, bounded state machine, immutable registration, recovery and controls.
2. Run the registered development campaign, perform actual agent review of epoch evidence, synthesize supported ideas, and write an honest scientific conclusion. Freeze one strategy for future confirmation. Execute a one-shot confirmation only if an independently eligible untouched period is supplied and frozen under its own protocol.

## Colony ownership

Forecast probability investigates calibration sparsity, raw versus calibrated probabilities, entropy, smoothing and strictly expanding historical recalibration. Timing/execution investigates permitted evidence grades, spreads, adverse-price stress and abstention; alternate decision times remain pending a verified replay input. Contract/relative-value investigates tails, interiors, YES/NO asymmetry, probability gaps and entry selection. Robustness/adversarial investigates fold concentration, best-day dependence, poor calibration and evidence degradation.

Each maintains its own parents and population. A proposal carries a causal rationale, parent IDs, data requirements, expected mechanism and a test that could falsify it. Deterministic local variants are labeled as such. They must never be advertised as autonomous model reasoning. Actual Codex research and criticism packets are recorded separately.

## Budget and gates

The immutable configuration caps discovery at eight epochs, 160 unique strategies and two hours from registration, whichever occurs first. Each epoch returns control for inspection; two stagnant epochs request new agent reasoning instead of spinning. Resuming never refunds time or evaluated candidates. Exhaustion, no improvement and insufficient evidence are valid outcomes.

Development promotion requires at least 30 selected dates, aggregate net return >=10%, mean estimated expected net return >=10%, at least four positive chronological folds, worst nonempty fold >=-10%, positive fixed-selection +2-cent stress, positive best-day-removed return, evidence quality >=0.65, and Brier no worse than the frozen reference. These are development screens, not inferential proof after adaptive selection. A/B+/B counts remain explicit; B/B+ are not verified fills. No single metric compensates for a failed gate.

## Architecture and artifacts

Agent hypothesis packets enter a validated typed specification. The evaluator reads only development records; one purchased contract at most per day. Exact historical fees and settlement mapping are retained. The controller records every unique result, rejects duplicate normalized specs, routes each result to another colony's deterministic falsification checks, and requires agent review before the next epoch. A Pareto archive preserves competing tradeoffs in return, expected return, calibration, sample, fold stability, evidence and stressed return. Synthesis records both parent IDs and refuses incompatible assumptions.

Registration binds code, configuration, input manifests, probability file and development labels. An OS advisory lock prevents duplicate execution. Writes are atomic. Stop is cooperative; Resume retains budget. Source changes after registration invalidate that run and require a transparently separate registration. Discovery has no holdout action.

Required evidence: data-capability audit; Fold 4 diagnostic; source inventory; colony charters; hypothesis schema; candidate registry; complete trade/abstention results; critique ledger; agent review packets; Pareto archive; progress by unique hypotheses and frontier changes; frozen strategy; development and final scientific reports. Unsupported feature families and unavailable confirmation must stay prominent in the report.

## Prohibited operations

Do not amend V5A source, registration, source data, counters, budgets, recovery state or holdout artifacts. No live feeds, credentials, network during replay, orders or purchases. Hosted Codex reasoning can inspect curated development evidence. A Python network denial is a replay guard, not a claim of an operating-system sandbox.
