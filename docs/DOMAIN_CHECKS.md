# Domain verification instructions

The generic controller records configured checks; it does not replace domain-specific validators. Implement or provision the required checks before accepting claims. Mixed work may need separate accepted scopes and checking environments for each output.

## Mathematics

Preserve the exact target, quantifiers, domain, definitions, regularity, boundary conditions and allowed axioms. Identify which variants settle the main question and which are only intermediate. Use one argument owner for dependent reasoning and workers for bounded lemmas, counterexamples, literature and formalization. Check lemma applicability to the target assumptions.

Label conjectures, informal arguments, checked calculations and formal proofs separately. Numerical patterns are exploratory evidence. When formal checking is available, review intended statement meaning, elaborated semantics, imports, definitions and proof dependencies as well as kernel acceptance. Record actual commands and toolchain versions. Without a formal checker, report the reviewed informal argument and remaining gap; do not claim a formal verification occurred.

## Computational research

Specify hypothesis, dataset snapshot, splits, baseline, metric, comparison budget, sample/uncertainty and multiplicity rules before the final evaluation. Diagnostic scaffolds validate feasibility; final acceptance must use the intended implementation and workload. Check mocks, substitutions, unintended subsampling, leakage, metric validity and baseline fairness against the code actually executed.

Register planned, attempted, completed, excluded and reported runs with actual settings, seeds, environments and failure/exclusion reasons. Replicate consequential measurements and test relevant robustness. Match numbers, figures and conclusions to stored outputs. Reproduction or narrative/log matching alone does not establish correct experimental design or generalization.

## Literature and evidence synthesis

Define scope, time horizon, source standard and coverage requirements. Retrieve primary materials with exact versions, dates and locators. Preserve contradictory findings and access gaps. Track shared source origins; repeated summaries of one source are not independent confirmations. Distinguish lack of retrieved evidence from evidence of absence. Novelty claims require a stated search scope and uncertainty.

## Empirical science

State measurable predictions, measurement protocol, controls, calibration, uncertainty, comparison rules and required expert review. Keep proposed experiments separate from performed measurements. Preserve raw data, negative results, deviations and actual settings. Accept only the tested scope and conditions; do not infer a broader mechanism without its discriminating evidence.

## Before delivery

Reconcile all attempts and exclusions; check dependency applicability, unresolved objections, actual outputs, source support and numerical claims. Preserve original target and accepted scope. Record unavailable checks explicitly. Report completion and individual hypothesis outcomes separately, with the next reproducible step for unresolved work.
