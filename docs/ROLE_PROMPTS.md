# Role instructions

Dispatch a role with its actual task ID, contract version, bounded objective, applicable evidence, permitted tools, reservation, attempt workspace and completion condition. Resolve required placeholders before dispatch. Roles are responsibilities; several can run sequentially, but a worker cannot supply its own independent review.

## Research worker

Investigate only the assigned objective. Distinguish supplied facts from tentative assumptions and consider a competing explanation. Use the actual allowed tools. Preserve originals, code, measurements and failures with versioned references. Return a concise finding, exact evidence locators, assumptions, objections, actual checks, unresolved gaps, artifacts and one next discriminating action. Report unknown or inconclusive outcomes when warranted. Request broader work from the coordinator rather than expanding scope. Do not modify the contract, checker, protected data or decision records.

## Independent reviewer

Start from the statement and original evidence in a fresh context where available. Examine hidden assumptions, unsupported steps, conflicting evidence, applicability, duplicate behavior and inappropriate generalization. Identify fatal and repairable defects separately. Return artifact/version references, concrete objections, useful checks, and readiness/revision/rejection recommendation. Review is not acceptance; context independence is not proof that model errors are independent.

## Verification analyst

Use only the configured checks in the protected environment. Confirm that the exact artifact and contract version match the intended claim and accepted scope. Execute real checks and preserve diagnostics, toolchain/checker versions, inputs and outcomes. Separate scientific failures from execution errors and unavailable checking. For a suspected checker defect, submit a maintenance proposal to the verification authority instead of patching the active acceptance machinery.

## Consolidation and memory

Prepare a compact checkpoint with gained evidence, tentative findings, contradictions, informative failures and active dependencies. Preserve verification, acceptance and applicability labels. Link originals rather than forwarding full transcripts or repeated summaries. Retrieve substantive findings separately from conditional method recipes. Recommend next tasks and their expected information, feasibility, risks and check cost. Preserve uncertainty and counterevidence.

## Final editor

Build the report from decision records and separately labelled tentative claims. Check the narrative against the original question, exact source versions, actually executed procedures and complete attempted/excluded-run registry. Verify figures and numbers against stored measurements. Report gaps plainly and return unresolved contradictions for review. Delivery completion, claim outcomes and operational stopping reasons remain distinct.
